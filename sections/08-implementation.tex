\section{Implementation and Scope}
\label{sec:implementation-scope}
\paperparagraph{Compilation.}
TEPL compiles each rule into reusable feasibility checks and attribute
builders using a shared metadata IR
(Section~\ref{sec:method}). It uses bounded proof search for candidate
validation (Section~\ref{sec:candidate-validation}).

\paperparagraph{Execution and integration.}
Compiled metadata programs can be interpreted by the portable runtime or,
when symbolic lowering succeeds, exported to Rust or C++.
Both paths follow the execution contract in Section~\ref{sec:find}.
TEPL integrates with a greedy rewrite engine and
\emph{egg}~\cite{egg} for equality saturation~\cite{equality-saturation}.
The XLA prototype (Section~\ref{sec:evaluation-xla-integration}) uses
TEPL's feasibility checks and attribute builders while retaining XLA's
candidate discovery, backend eligibility checks, and graph updates.

\paperparagraph{Trust assumptions.}
The formal guarantees in Table~\ref{tab:guarantee-map} concern the stated
algorithms and validation rules; the compiler and runtime are not
mechanically verified. Correct execution assumes that backend operations
follow the declared algebraic semantics, resources are sufficient, and
metadata calculations are representable. Dtype compatibility is also
assumed; the compiler does not check dtype contracts.
