\subsection{Operation Semantics}
\label{app:operation-semantics}
The \code{semantics} block defines the value at each output coordinate.
Its \code{yield} expression combines operand reads, scalar arithmetic,
and summation. An operand name reads an element using the coordinates
assigned by the \code{axes} bindings. For example, nonbroadcasting
addition binds corresponding operand axes to one group and uses
\code{yield Add(lhs, rhs)} to add elements at the same coordinates.

The expression \code{Reduce(G, e)} sums \code{e} over all coordinates
of group \code{G}, holding the other coordinates fixed. In
Listing~\ref{lst:dot-declaration}, \code{Product(lhs, rhs)} multiplies
operand elements, and \code{Reduce(K, ...)} sums these products over
the contraction axes. Reducing an empty group leaves the expression
unchanged.

Explicit reads use \code{Read(input, indices)}, where \code{indices}
provides one coordinate per input dimension. The expression \code{Coords(G)}
returns the current coordinates in group order. Index expressions can
scale or offset these coordinates before reading an input. For example,
a static slice reads at \code{starts + strides * output_indices}.
These calculated accesses extend the operation semantics beyond the
direct whole-axis completeness theorem.

index primitives.
