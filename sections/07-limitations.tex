\subsection{Coverage}
\label{sec:coverage}

\paragraph{Can TEPL cover all tensor operations?}
In principle, yes, as a language for writing custom tensor rewrite patterns.
Users can declare operations in a dialect, write rules in algebraic form,
and manually specify attribute transformations and applicability conditions
using \code{derive} and \code{where}. This manual path does not require
operation semantics in Axes IR, so it can express rewrites beyond the
automatic inference fragment. For operations without declared semantics,
the user is responsible for the rewrite's correctness.

\paragraph{Can TEPL infer attributes for all operations?}
No. Automatic attribute inference requires the operations to have semantic
definitions in Axes IR. Axes IR mainly describes computations through axes,
with limited support for explicit index calculations, such as those used
by static slice and reverse. It cannot currently describe accesses that
depend on tensor-valued indices. For example, dynamic slice takes runtime
start indices as tensor operands and slice sizes as attributes. The start
indices select elements within axes; describing this access requires more
than identifying or rearranging axes. Table~\ref{tab:semantic-coverage}
summarizes the current coverage of Axes IR and the synthesis guarantees.

\paragraph{Is attribute inference complete for every supported operation?}
No. The mathematical algorithm is complete only for the contraction-family
fragment in Section~\ref{sec:formal-scope}: it finds valid attributes whenever
they exist (Theorem~\ref{thm:complete-synthesis}). The current implementation
covers part of this fragment (Section~\ref{sec:implementation}).

For other Axes IR operations, TEPL can verify custom algebraic rewrites using
supported primitives and arithmetic laws. Its contract is \emph{soundness}:
accepted attributes must yield legal, equivalent replacements under the
rule's conditions and arithmetic policy. TEPL may still fail to prove a
correct rewrite or discover attributes that it can verify when supplied manually.

\subsection{Scalability}
We assess scalability along two dimensions: the number of operations in a
rewrite chain and tensor rank. Longer chains require reasoning across more
operations, while higher ranks increase the number of axes involved.
We measure how attribute construction and verification time changes along
each dimension. Appendix~\ref{app:scalability} presents the experiments,
results, and measurement limits.
