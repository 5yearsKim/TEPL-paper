\subsection{XLA Pass Integration: Inventory and Protocol}
\label{app:xla-integration}
The experiment uses the actual XLA \code{TransposeFolding} pass and its complete
25-test source inventory, independently of which branches TEPL supports. The
evaluated checkout and exact upstream pass/header/test bytes are pinned in
\code{evaluation/xla-integration/}. Twenty modules are literal HLO strings;
five use the original builder prefix up to the first assertion. Assignment
assertion macros become status-returning macros; module creation uses the normal
module factory. Shapes, operands, windows, dimension numbers and permutations
are retained. The builder-only constant-call test remains a no-op control.

\paragraph{Implementation boundary.}
The hybrid uses a copy of the upstream pass with only the dot-attribute helper
redirected to a native TEPL C ABI. Traversal, eligible-operand selection,
backend callbacks, replacement, precision and metadata propagation are retained.
Convolution construction stays handwritten. The one custom-callback dot case
also retains handwritten construction; it is outside the default-policy
certificate and is counted explicitly. No fallback occurs for an admitted
default dot candidate. The prototype handles dense f32 dots, not every dtype,
sparse variant or auxiliary-operand form accepted by XLA.

Two TEPL templates omit all eight RHS axis fields. Their guards retain the
default pass's nonidentity, rank, contraction-count and fixed-batch conditions.
The single-free-axis certificate in Appendix~\ref{app:accepted-core-proof}
establishes feasibility. The bridge loads the accepted portable program once,
constructs a local metadata view of the selected operands, checks source
legality and the guard on misses, and evaluates the cached attribute DAG. A
bounded 256-entry cache memoizes successful outputs by rule side and the complete
input metadata: both shapes, permutation, and all source dot lists. Exact-key
hits reuse an already checked result; failed checks are never cached. Shape
extents are included, so changing paired extents cannot bypass legality. This
is memoization of a deterministic metadata function, not an extra assumption.
Unchanged HLO
operands remain opaque tensor inputs to this metadata computation. No numerical
convolution or call semantics is supplied by the TEPL core for those operands.

The upstream helper has four explicit permutation-remapping sites. The
inferred templates contain none. This is automation of a specific attribute
responsibility, not net source-size or developer-time savings: the reusable C ABI
and HLO adapter introduce additional code, retained in full in the artifact.

\paragraph{Checks and measurement.}
Each original module and both resulting modules pass XLA's verifier. Full HLO
text and changed/no-change results must agree between the upstream and hybrid
passes. Deterministic dense inputs are interpreted using XLA's HLO evaluator;
sparse/additional convolution operands are explicitly outside that numerical
harness. These cases still undergo HLO comparison and verification and use
only the original handwritten convolution path.

One warmup and ten measured rounds per case use batches of 100 precloned
modules, rotating the three variant orders. The timer includes the entire pass:
traversal, guards, metadata evaluation, replacement and deletion. Parsing,
cloning, shared-library/program loading, HLO comparison and numerical execution
are excluded. The archived aggregate is the median over ten rounds of
the sum of all 25 case batch means, representing one pass per test module.
All 825 raw samples are retained, including warmup. Timing uses one machine;
no confidence interval or whole-compiler slowdown is inferred.
Cold-cache samples clear entries before each module within the timer; warm-cache
samples first run one untimed clone and require zero misses in the timed batch.
Cold samples require zero hits. All hit/miss counts are retained. The initial
uncached implementation and its measurements are preserved separately; warm
latency is not an estimate of an unmeasured production cache hit distribution.

This demonstrates integration into an existing optimizer pass under its actual
control flow, with unsupported branches retained visibly. Upstream tests do
not establish production-model opportunity frequency, general tensor-rewrite
coverage, developer productivity or end-to-end optimizer speedup.
