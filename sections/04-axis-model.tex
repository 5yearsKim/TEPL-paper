\section{Axis-Based Representation}
\label{sec:axis-model}
How can we tell whether two tensor expressions perform the same computation?
Within the scope defined in Section~\ref{sec:formal-scope}, we answer this
by tracking how input dimensions are connected and how output axes are ordered.

\subsection{Logical Axes}
\label{sec:logical-axes}
Consider matrix multiplication,
\code{einsum('ik,kj->ij', A, B)}~\cite{numpy-einsum}.
The second dimension of $A$ and the first dimension of $B$ both
carry the index \code{k}: they use the same coordinate during
multiplication. We therefore treat them as one \emph{logical axis}.
The indices \code{i} and \code{j} identify two other logical axes.

A dimension's position is local to its tensor, while a logical axis
connects dimensions that use the same coordinate.
We identify an input dimension by $(X,d)$, where $X$ is the input
tensor and $d$ is its zero-based dimension position.
For an expression with input set $\mathcal X$, the input dimensions are
\begin{equation}
 \mathcal D=\{(X,d)\mid X\in\mathcal X,\ 0\le d<\operatorname{rank}(X)\}.
\end{equation}
We write $u\sim v$ when dimensions $u$ and $v$ use the same coordinate.
Each group of such dimensions forms an equivalence class, or logical
axis. For the LHS expression $L$, the logical axes are
\begin{equation}
 \Axes(L)=\mathcal D/{\sim}.
\end{equation}
Here $\mathcal D/{\sim}$ denotes the set of these equivalence classes.

Logical axes record coordinate connections, not just dimension sizes.
Two dimensions with equal extents need not belong to the same logical
axis. We also retain axes removed by summation: in the example,
\code{k} is absent from the output but still records the connection
between $A$ and $B$.

\subsection{Symbolic Axis Groups}
\label{sec:symbolic-axis-groups}
A \emph{symbolic axis group} represents an ordered sequence of distinct
logical axes whose length need not be known at compile time. We write groups
as $\vec I$, $\vec J$, or $\vec K$. For example,
$\vec K=(k_1,\ldots,k_r)$ represents $r$ axes, where $r$ may vary across
matches. This allows one symbolic description to cover tensors of different
ranks.

Group order matters because operation attributes refer to dimension
positions. We write $\vec I\Vert\vec K$ for concatenation and
$\operatorname{set}(\vec I)$ for the corresponding unordered set. When a
group appears in both operands, corresponding entries denote the same
logical axes. For example, an unbatched contraction with operand orders
$\vec I\Vert\vec K$ and $\vec K\Vert\vec J$ sums over $\vec K$ and
produces output order $\vec I\Vert\vec J$.

\subsection{Axis Representation}
\label{sec:axis-representation}
For an expression $T$ with assigned attributes, define
\begin{equation}
 N(T)=(\mathcal D,\sim,\operatorname{Ord}_{\mathrm{out}}),
 \label{eq:axis-representation}
\end{equation}
where $\mathcal D$ is the set of input dimensions, $\sim$ records their coordinate
connections, and $\operatorname{Ord}_{\mathrm{out}}$ lists the output classes in dimension order. This representation
specifies the value at each output coordinate: use the same index at
connected input dimensions, multiply the selected input entries, and sum over
all classes absent from $\operatorname{Ord}_{\mathrm{out}}$. Classes in $\operatorname{Ord}_{\mathrm{out}}$ remain as output coordinates.

For matrix multiplication $T=AB$, contraction identifies
$(A,1)\sim(B,0)$, giving the classes:
\begin{equation}
 i=\{(A,0)\},\qquad k=\{(A,1),(B,0)\},\qquad j=\{(B,1)\}.
\end{equation}
Thus
\begin{equation}
 N(T)=\bigl(\{(A,0),(A,1),(B,0),(B,1)\},\sim_{AB},(i,j)\bigr).
\end{equation}
The class $k$ is absent from the output, giving $T_{ij}=\sum_k A_{ik}B_{kj}$.

\subsection{Equivalence of Axis Representations}
\begin{lemma}[Axis exactness]
\label{lem:axis-exactness}
Under the assumptions in Section~\ref{sec:formal-scope}, for two legal
components $L,R$ over the same inputs at fixed match metadata,
\begin{equation}
 \forall X,\quad L(X)=R(X)\quad\iff\quad N(L)=N(R).
 \label{eq:axis-exactness}
\end{equation}
\end{lemma}
Axis names do not matter: two computations agree on every input exactly when
their input-dimension connections and output-axis order agree. Attribute
synthesis therefore reduces to choosing legal RHS axis fields that reproduce
the LHS representation (Section~\ref{sec:mathematical-synthesis}).
Appendix~\ref{app:axis-exactness} gives the proof and a concrete example.
