\subsection{Attribute Program Synthesis}
\label{sec:synthesis}
Synthesis matches value expressions, determines which axes each replacement
operation preserves or reduces, and queries mappings for its attributes.
Figure~\ref{fig:auto-matching} previews distribution: matching reads in the
normalized source and RHS arithmetic skeleton supplies coordinate
correspondence before replacement attributes are known. With no broadcasting
and order-preserving addition, both replacement dots reuse the source
descriptor. The figure's $A[I,K],B[I,K],C[K,J]$ abbreviate group coordinates,
not necessarily contiguous layouts; question marks denote unresolved
reductions. Construction precedes equivalence checking.

\paperfigure{1}{figures/Auto attribute matching_ from rules to attributes.pdf}{Matching normalized operand reads supplies coordinate correspondences for constructing replacement attributes.}{fig:auto-matching}{Three stages connect a distribution rule and operation semantics to normalized
terms, read matching, position queries, and completed replacement descriptors.}
For reconstruction beyond reuse, continue reassociation with source
$T=\operatorname{dot}(X,Y)$, replacement $U=\operatorname{dot}(Y,Z)$,
and final outputs $O,O'$.

\subsubsection{Value Expression Normalization}
\label{sec:normalization}
A normalized expression is a sum of terms with coefficients, indexed reads,
and symbolic reduction sequences, similar in representation to SPORES's
R-polynomials~\cite[Section~2.3, Definition~2.4]{spores}:
\begin{equation}
 t=(c,[r_1,\ldots,r_m],R),\qquad
 \operatorname{value}(t)=\sum_R c\prod_{i=1}^{m}r_i.
 \label{eq:normalized-term}
\end{equation}
Reads retain tensor identity and coordinates. The empty product is 1, an empty
reduction sequence means no summation, and an empty term list denotes zero.
The representation similarity transfers no completeness claim.
For reassociation, $\sum_L(\sum_K XY)Z$ normalizes to $\sum_{L,K}XYZ$
only after establishing that $Z$ is independent of $K$, the reduction groups
are disjoint, and the selected arithmetic policy permits the required laws.

Normalization separates the grouping of arithmetic operations from the
coordinates of their reads. For example, $X(Y+Z)$ produces two terms with
reads $[X,Y]$ and $[X,Z]$, while the reassociation example produces one term
with reads $[X,Y,Z]$. In the latter case the compiler proceeds as follows:
\begin{equation}
 \sum_L\left(\sum_K XY\right)Z
 \;=\;\sum_L\sum_K XYZ
 \;=\;\sum_{L,K}XYZ.
\end{equation}
The inner dot contributes $X,Y$ and reduction group $K$; multiplication
adds the read of $Z$; the outer dot contributes $L$. The normalized term
therefore retains both the reads and the full reduction sequence $L\catseq K$.
Operand names here abbreviate indexed reads with the source mappings already
established.

Unknown RHS attributes leave its reductions and coordinates unavailable.
Synthesis therefore normalizes an \emph{arithmetic skeleton} that expands
value operations while temporarily omitting axes. The skeleton of $X(YZ)$
contains reads $[X,Y,Z]$ and coefficient 1; its empty reduction sequence does
not assert that the completed RHS has no reductions. Corresponding terms and
reads reuse source coordinates. Multiple possible assignments must be shown
to agree or remain unresolved. Read correspondence guides construction;
coefficients, reduction domains, and full equivalence are checked afterward.

For $X(YZ)$, matching identifies the reads of $Y$ and $Z$ as inputs to the
new intermediate $U$, and the read of $X$ as an input to the final dot.
Each read receives the corresponding source coordinates. This establishes
which logical axes occur in each replacement input, but leaves their new
roles open: an axis reduced by one source operation may need to survive a
different operation in the replacement.

\subsubsection{Determine Which Axes Each Operation Preserves}
\label{sec:keep-axes}
Read correspondence identifies the logical axes used by each replacement subtree.
An intermediate must preserve coordinates needed outside its replacement
subtree or in the final output. For one matched product, let
$\Axes_{\mathrm{in}}(t)$ and $\Axes_{\mathrm{out}}(t)$ collect logical axes
used by reads inside and outside that subtree; $\Axes(O)$ denotes source
output axes. The required set is
\begin{equation}
\begin{aligned}
 \Keep(t)&=\Axes_{\mathrm{in}}(t)\cap\\
 &\quad(\Axes_{\mathrm{out}}(t)\cup\Axes(O)).
\end{aligned}
\label{eq:keep-axes}
\end{equation}
These sets ignore order, which is constructed later. Required sets must agree
across matched products. Axes used only inside can be reduced where semantics
permit; axes used only outside need not pass through $t$.

The preservation rule follows from what reduction removes. Once an
intermediate sums over an axis, its consumers can no longer select a value
at a particular coordinate of that axis. An outside read that uses the same
coordinate must still pair with the intermediate at that coordinate.
Similarly, an output axis must survive to distinguish output elements.
These two requirements explain the union in Equation~\eqref{eq:keep-axes}.
The intersection excludes coordinates that never occur inside the
intermediate's computation.

For $U$, the inside reads are $Y,Z$ and the outside read is $X$. Source
mappings give $Y$ the groups $B,K,\Jsel,\Jrem$ and $Z$ the groups
$B,\Isel,\Jsel,F$. These lists state membership, not physical order.
Table~\ref{tab:keep-decisions} explains each decision. In particular, $K$
was reduced by the source inner dot but must survive $U$ to pair with $X$.
Conversely, $\Irem$ is needed in the final output but need not pass through
$U$: it reaches the final dot directly through $X$.

The same reasoning uses the declared groups of other operations. For a group
$g$ bound to operands in a nonempty set $E_g$, first select the axes occurring
in exactly those operands:
\begin{equation}
 \begin{aligned}
 D_g&=\left(\bigcap_{i\in E_g}\Axes(x_i)\right)\\
 &\quad\setminus\left(\bigcup_{i\notin E_g}\Axes(x_i)\right).
 \end{aligned}
\end{equation}
If the value definition reduces $g$, its candidates are
$D_g\setminus\Keep(t)$; otherwise they are $D_g\cap\Keep(t)$.
For a dot, both batch and contraction groups occur in both operands.
Whether their coordinates must survive distinguishes the two roles.
This assigns membership; ordered positions are constructed next.
Ambiguous declared roles remain unresolved, and explicit output-domain groups
are handled separately.

\subsubsection{Construct Attributes from the Mapping Table}
\label{sec:attribute-construction}
A query $\pos(P,G)$ returns positions selecting ordered group $G$ in $P$.
Both sides of a paired binding query the same group order.
\begin{figuretext}{figures/Constructing Dot Attributes from Axis Mappings.pdf}{Paired position queries construct dot attributes; the completed intermediate supplies mappings for the final dot.}{fig:attribute-construction}{Paired queries on Y and Z construct the inner dot, an interface bridge
establishes U's layout, and paired queries on X and U construct the final dot.}
Figure~\ref{fig:attribute-construction} first constructs $U$'s contraction
lists, then uses $U$'s completed interface for the final dot. Its unbatched
example abbreviates contraction fields and writes $G=\Isel\catseq K$.
Group chips indicate membership, not physical order.

Let $b_X,b_Y,b_Z$ locate $B$, let $k_X,i_X$ locate $K,I$ in $X$, and let
$j_Y$ locate $J$ in $Y$. Equation~\eqref{eq:z-partners} gives $z_J$.
For $U$, batch lists are $b_Y,b_Z$ and contraction lists are
$\gath(j_Y,v_J),z_J$. Taking ordered complements of those positions gives
free lists $f_Y^U,f_Z^U$ and interface
\begin{equation}
\begin{aligned}
 P_U&=B\catseq\gath(P_Y,f_Y^U)\\
 &\quad\catseq\gath(P_Z,f_Z^U).
\end{aligned}
\label{eq:u-interface}
\end{equation}
This retains physical operand order even when surviving groups interleave.

The compiler publishes the resulting $P_U$ and its group mappings before
constructing the final dot. Merely listing $U$'s retained groups would not
specify this layout: $K$ and $\Jrem$ can be interleaved in $Y$, and
$\Isel$ and $F$ can be interleaved in $Z$. Ordered complements retain
those arrangements, and the dot's output convention places the left free
axes before the right free axes.

\end{figuretext}
In particular, the free lists are
\begin{equation}
\begin{aligned}
 f_Y^U&=\ocomp(\rho(P_Y),b_Y\catseq\gath(j_Y,v_J)),\\
 f_Z^U&=\ocomp(\rho(P_Z),b_Z\catseq z_J).
\end{aligned}
\end{equation}
The final dot uses batch lists $b_X,\rho(B)$ and contraction lists
\begin{equation}
\begin{aligned}
 c_L^{O'}&=\gath(i_X,v_I)\catseq k_X,\\
 c_R^{O'}&=\pos(P_U,\Isel)\catseq\pos(P_U,K).
\end{aligned}
\end{equation}
Both lists select $\Isel\catseq K$, following source reduction order
$L\catseq K$ filtered to the remaining contractions. Fixed bindings determine
order when present; otherwise construction prefers source reduction or output
order, then operand order. Removing contractions leaves
$P_{O'}=B\catseq\Irem\catseq\Jrem\catseq F=P_O$.
These are candidate attributes, still subject to legality and value checking.

\subsubsection{Produce and Verify Attribute Programs}
\label{sec:emit-programs}
The compiler resolves group queries and intermediate interfaces to source
attributes and shapes. For example,
\begin{equation}
 c_R^U=\gath\bigl(c_R^{\mathrm{outer}},
 \mpo(c_L^{\mathrm{outer}},|B|+|I|+\rho(J))_1\bigr),
 \label{eq:source-only-example}
\end{equation}
where subscript 1 selects the first returned list. Group lengths also derive
from source metadata. Emitted programs contain no unresolved RHS attributes
or logical-group queries and do not access tensor elements.

The expression has two steps: find which outer contraction slots select
axes from $J$, then select their partners from the right contraction list.
In the partitioning figure, those steps yield $u_J=[0]$ and $c_R^U=[2]$.
The emitted expression keeps the symbolic operations, so it can compute
different lists for other legal matches of the same rule. Queries involving
$P_U$ are resolved by substituting its constructed layout and composing
mappings until only source attributes and shapes remain. Thus synthesis
produces a reusable computation for each attribute, rather than a single
list for one tensor shape.

Supported calculated accesses additionally match index coefficients and
offsets. For example, two static slices access the original input at
$s_i+d_i(s_o+d_o q)$, where $s_i,d_i$ are the inner start and stride,
$s_o,d_o$ are the outer ones, and $q$ is an output coordinate. Expanding this
expression gives candidate attributes for a combined slice:
\begin{equation}
 s'=s_i+d_i s_o,\qquad d'=d_i d_o.
\end{equation}
The calculation applies per axis; resulting access bounds and output shape
still require checking. This illustrates how index expressions supply
attributes beyond axis-position lists. Coupled or inverse equations beyond
the supported fragment remain unresolved.

The completed RHS reduces $\Jsel$ inside $U$ and $\Isel\catseq K$ in the
final dot. Its actual reads, coefficients, reduction domains, and output
interface can now be compared with the source under permitted laws.
In abbreviated indexed notation, the comparison is
\begin{equation}
 e_{\mathrm{RHS}}
 =\sum_{\Isel,K}X\left(\sum_{\Jsel}YZ\right)
 =\sum_{\Isel,K,\Jsel}XYZ.
\end{equation}
The selected subgroups cover $L$, and their mappings retain the original
operand pairings. This allows comparison with the source's
$\sum_{L,K}XYZ$ when the arithmetic policy permits the required changes
in reduction order. The check uses the actual constructed descriptors and
output layout.
A fresh context reconstructs the completed rule from emitted programs.
Construction obligations must follow from source legality and the declared
guard; they cannot become new assumptions.

\subsubsection{General Synthesis Algorithm}
\label{sec:synthesis-algorithm}
Algorithm~\ref{alg:synthesis} retains $(V,M,\Pi)$ and proposed
constructors $C$. After source normalization and read matching, it processes
replacement operations after their inputs, selects and orders groups, fills
attributes through position and supported index queries, and lowers each
completed operation. Every completed node must have legal resolved attributes,
a consistent interface and value expression, and valid mappings.
Explicit output-domain groups come from required output axes absent from all
operands; their sizes determine domain attributes. Whole-rule checking,
source-only resolution, and fresh-context verification precede success.
Unsupported or unproved steps return unresolved results.

\begin{paperalgorithm}[H]
\caption{Synthesize and check replacement attribute programs.}
\label{alg:synthesis}
\begin{lstlisting}[language=Python]
def synthesize_attribute_programs(rule):
    V, M, partitions = build_symbolic_axis_mapping(rule.lhs)
    source = normalize(V[rule.lhs].value)
    skeleton = normalize(arithmetic_skeleton(rule.rhs))
    match = correspond(source, skeleton)
    required = required_output_axes(match, V[rule.lhs].axes)
    bind_replacement_reads(V, match)
    C = {}
    for op in producer_first(rule.rhs):
        if op.is_input:
            continue
        inputs = [V[t] for t in op.inputs]
        if op.has_attribute_holes:
            groups = select_groups(op.definition, inputs, required[op])
            groups = order_groups(groups, op, source, inputs)
            for binding in op.unresolved_axis_bindings:
                P = inputs[binding.operand].axes
                G = groups[binding.group]
                C[op, binding.attribute] = positions(P, G, M, partitions)
            complete_other_attributes(op, inputs, groups, match, C)
        completed = substitute_attributes(op, C)
        V[op] = lower_and_check(completed, inputs, M, partitions)
    check_equivalence(V[rule.lhs], V[rule.rhs])
    programs = source_only_expressions(C)
    verify_in_fresh_context(rule, programs)
    return programs
\end{lstlisting}
\end{paperalgorithm}
The table $C$ is indexed by both operation and attribute, so the two
replacement dots can have different constructors for identically named
fields. This makes explicit the scope of each proposed expression.
\code{lower_and_check} publishes a completed operation's interface and
mappings for its consumers, as $U$ supplies the layout needed by the final
dot. \code{complete_other_attributes} handles supported index expressions,
output domains, and output permutations. The last three steps check the
whole replacement, resolve programs to source metadata, and reconstruct the
rule in a fresh context. Appendix~\ref{app:synthesis} gives further details
on the helper operations and their unresolved outcomes.
