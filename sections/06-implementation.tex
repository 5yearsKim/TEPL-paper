\section{Implementation}
\label{sec:implementation}
\label{sec:symbolic-bridge}
\paragraph{Compiler architecture.}
The TEPL compiler processes rewrite rules and dialect declarations through
ANTLR~\cite{antlr} parsing, import and name resolution, and type checking. For rules
with declared semantics, it then lowers operation semantics, synthesizes
missing attributes, and verifies the completed rewrite. The compiler lowers
the resulting rules to an executable representation. The rewrite engine
uses this representation to match input graphs at runtime. Attribute holes have already been replaced by executable
computations over source metadata, so applying a rule evaluates these
computations without repeating attribute inference.

\paragraph{Runtime integration.}
TEPL provides a greedy graph-rewriting engine. Users construct an input
graph using operations from declared dialects and supply compiled rewrite
rules. The engine repeatedly matches and applies applicable rules, returning
the rewritten graph when no further rewrite applies or an execution limit
is reached.

The compiled representation also supports integration with other rewrite
engines. As a concrete example, TEPL provides an integration with
\emph{egg}~\cite{egg}, generating Rust code from compiled rules to enable
equality saturation~\cite{equality-saturation} of tensor expressions. The integration supports
conditional rewrites using tensor shape and dtype information maintained
by e-class analysis. Matching also binds attributes from matched operation
nodes, making them available to rule conditions and replacement attribute
computations. This integration demonstrates TEPL's potential applicability to other
tensor compiler stacks.
