\section{Mathematical Attribute Synthesis}
\label{sec:mathematical-synthesis}
We now construct RHS attributes from the LHS axis representation. Logical
axes and the target output order $F$ always come from the LHS. The algorithm
has three passes: find the axes that survive at each node, check whether
the required orders are possible, and construct attributes. It does not
enumerate possible attribute assignments.

\subsection{Canonical Intermediate Axes}
\label{sec:canonical-axes}
For each RHS node $v$, let $U_v$ be the inputs in its subtree. For a logical
axis $a$, let $\sigma(a)$ be the inputs containing a port in that class.
First determine the \emph{mandatory axes} $M_v$: axes used inside the subtree
that must reach the final output or connect to an input outside the subtree.
\begin{equation}
 M_v=\left\{a\in\mathcal A\;\middle|\;
 \begin{aligned}
 &\sigma(a)\cap U_v\ne\varnothing\ \land\\[-2pt]
 &(a\in\operatorname{set}(F)\ \lor\ \sigma(a)\nsubseteq U_v)
 \end{aligned}\right\}.
 \label{eq:mandatory-axes}
\end{equation}
These axes cannot be removed at $v$. However, an operation may also have to
retain an axis that is no longer needed. A contraction, for example, cannot
sum away an axis found in only one operand: that axis is free.

Let $P_v$ be the \emph{canonical live set}, the axes actually retained at
$v$ by our algorithm. Always $M_v\subseteq P_v$. The choice is canonical
because we remove each unnecessary axis at the earliest operation that can
legally remove it. Here $P$ is the set of all input ports, while $P_v$ is a
set of logical-axis classes; they are different objects.

Let $I_X$ list the axes of input $X$ in their actual order, using LHS class
names. For matrix multiplication, $I_A=(i,k)$ and $I_B=(k,j)$. Process the
RHS from children to parents using Table~\ref{tab:canonical-live}.
\begin{table}[!htbp]
\caption{Canonical live sets. A unary node has child $u$.}
\label{tab:canonical-live}
\begin{tabularx}{\linewidth}{@{}llY@{}}\toprule
Node & $P_v$ & Reason\\\midrule
Input $X$ & $\operatorname{set}(I_X)$ & Start with all input axes.\\
Permutation & $P_u$ & Change order, not membership.\\
Unary summation & $P_u\cap M_v$ & Retain only mandatory axes.\\
Contraction & $B_v\cup LF_v\cup RF_v$ & Retain batch and free axes.\\\bottomrule
\end{tabularx}
\end{table}
For a contraction with children $\ell,r$, define
\begin{equation}
\begin{aligned}
 B_v&=P_\ell\cap P_r\cap M_v,&
 K_v&=(P_\ell\cap P_r)\setminus M_v,\\
 LF_v&=P_\ell\setminus P_r,&
 RF_v&=P_r\setminus P_\ell.
\end{aligned}
\label{eq:canonical-roles}
\end{equation}
These are the batch, contraction, left-free, and right-free axes. A shared
axis stays as batch if it is mandatory, and is contracted otherwise. An
axis is \emph{complete} in a subtree when all its supporting inputs are
inside it. Thus contraction removes shared, complete, non-output classes;
unary summation can remove any remaining complete, non-output classes.
One-sided axes remain free even when they are no longer mandatory.

Induction from the inputs shows $M_v\subseteq P_v$ and that every class in
$P_v$ has support in $U_v$. At the root, check
\begin{equation}
 P_{\mathrm{root}}=\operatorname{set}(F).
 \label{eq:root-live}
\end{equation}
Extra axes may survive intermediate nodes, but none may remain in the final
output.

\subsection{Why the Canonical Choice Does Not Lose Solutions}
\label{sec:canonicalization}
For an assignment $\beta$, write $\operatorname{Ord}_v(\beta)$ for the
output axis order at node $v$. For a sequence $S$ and a set $Q$, $S|_Q$
keeps only members of $Q$, in their original order. By
Lemma~\ref{lem:axis-exactness}, any valid RHS has the LHS partition, so its
intermediate axes can be named using LHS classes.

\begin{lemma}[Canonicalization preserves feasibility]
\label{lem:canonicalization}
If a valid assignment $\beta$ exists, a valid assignment $\beta'$ exists with
\begin{equation}
 \forall v,\qquad
 \operatorname{Ord}_v(\beta')=\operatorname{Ord}_v(\beta)|_{P_v}.
 \label{eq:canonicalization}
\end{equation}
\end{lemma}
The lemma does not say that every solution has the same intermediate axes.
It says that whenever a solution exists, one exists with our canonical live
sets and the same relative order of surviving axes.

For example, let $A,B$ have shape $[2]$ and consider the RHS
$\operatorname{sum}(\operatorname{dot}(A,B))$. A valid assignment can keep
the shared axis as batch and sum it later. The canonical assignment contracts
it immediately:
\begin{table}[!htbp]
\caption{Two ways to compute the scalar $A_0B_0+A_1B_1$.}
\label{tab:canonical-example}
\begin{tabularx}{\linewidth}{@{}lYll@{}}\toprule
Assignment & Dot $(b_\ell,b_r,k_\ell,k_r)$ & Dot shape & Sum axes\\\midrule
$\beta$ & $([0],[0],[],[])$ & $[2]$ & $[0]$\\
$\beta'$ & $([],[],[0],[0])$ & $[]$ & $[]$\\\bottomrule
\end{tabularx}
\end{table}
Summation over an empty list leaves its input unchanged.

\begin{proof}
Starting from $\beta$, remove only axes outside $P_v$ and preserve the order
of the others. We prove two properties together, from children to parents:
\begin{equation}
\begin{gathered}
 P_v\subseteq\operatorname{set}(\operatorname{Ord}_v(\beta)),\\
 \operatorname{Ord}_v(\beta)|_{P_v}
 \text{ can be realized by legal attributes.}
\end{gathered}
\end{equation}
Mandatory axes must survive in the original assignment too: a removed axis
cannot later reconnect to another input or become an output axis.

Inputs remain unchanged. A permutation can arrange the child's surviving
axes in the required order. Unary summation retains exactly
$P_v=P_u\cap M_v$. These axes also survive in the original output, and
summation preserves their relative order.

At a contraction, consider three cases.
\begin{enumerate}
\item \emph{Shared axes must connect here.} Every axis in $P_\ell\cap P_r$
also occurs in both original children. The original assignment must connect
these two occurrences at this node. Otherwise they become two separate
axes in the same subtree, and no later operation can merge them.
\item \emph{Mandatory shared axes stay; the others can be summed now.}
Every axis in $B_v$ is needed later, so it is also a batch axis in the original
assignment. Every axis in $K_v$ is complete and absent from the final output.
It can be contracted now even if the original assignment kept it as batch.
\item \emph{Free axes keep their roles.} Suppose $a\in LF_v$ also occurred
in the original right child's output. It then has support in both children,
so it must be mandatory in the right child: $a\in M_r\subseteq P_r$.
This contradicts $a\in P_\ell\setminus P_r$. Thus it was left-free in the
original assignment too. The right-free case is the same.
\end{enumerate}
Consequently $P_v=B_v\cup LF_v\cup RF_v$ is a subset of the original output
axes, with the same surviving roles. Order $B_v$ as in the original batch
list, and list $K_v$ in the same order on both sides. Free axes inherit the
filtered child orders. The result is exactly
$\operatorname{Ord}_v(\beta)|_{P_v}$.

Each selected axis occurs once, corresponding extents agree, and batch and
contraction positions are disjoint. The attributes are therefore legal.
Only occurrences of the same LHS class connect, and a class is removed only
after all its input connections are complete. Moving these finite sums
earlier preserves the represented computation under exact arithmetic.

At the root, the mandatory axes and the original output axes are both
$\operatorname{set}(F)$. The inclusion just proved gives
\begin{equation}
 \operatorname{set}(F)\subseteq P_{\mathrm{root}}
 \subseteq\operatorname{set}(F).
\end{equation}
The final order remains $F$ and the port connections are unchanged.
Lemma~\ref{lem:axis-exactness} therefore makes $\beta'$ valid.
\end{proof}

\subsection{Ordering Feasibility}
\label{sec:ordering-feasibility}
Choosing axis sets is not enough. Each operation also restricts output
order. Let $Req_v$ be an ordered subsequence that the output at $v$ must
contain. Write $A\preceq B$ when $A$ is a subsequence of $B$, and
$A\Vert B$ for concatenation. Propagate requirements from root to inputs:
\begin{align}
 Req_{\mathrm{root}}&=F,\\
 Req_u&=[] &&\text{at a permutation},\\
 Req_u&=Req_v &&\text{at unary summation},\\
 Req_\ell&=Req_v|_{LF_v},\qquad
 Req_r=Req_v|_{RF_v} &&\text{at contraction}.
\end{align}
A permutation can impose any output order, so it passes no order requirement
to its child. Summation preserves order, so it passes the same requirement.
A contraction inherits free-axis order from its children, but chooses batch
order through its own attribute lists. Batch-order requirements therefore
stay at the contraction.

At each contraction, the required sequence must respect its three output
blocks:
\begin{equation}
 Req_v=(Req_v|_{B_v})\Vert(Req_v|_{LF_v})\Vert(Req_v|_{RF_v}).
 \label{eq:block-order}
\end{equation}
At an input node, its fixed axis order must contain the requirement:
\begin{equation}
 Req_v\preceq I_v.
 \label{eq:input-order}
\end{equation}
Combining these with the root live-set check gives
\begin{equation}
\begin{aligned}
 \operatorname{check}(p)={}&[P_{\mathrm{root}}=\operatorname{set}(F)]\\
 &{}\land\bigwedge_{\text{input }v}[Req_v\preceq I_v]\\
 &{}\land\bigwedge_{\text{contraction }v}
 \left[Req_v=(Req_v|_{B_v})\Vert(Req_v|_{LF_v})\Vert(Req_v|_{RF_v})\right].
\end{aligned}
\label{eq:feasibility}
\end{equation}
These checks are functions of source metadata: it determines the LHS
classes, input orders, and target output order.

\subsection{Constructing Attributes}
\label{sec:formal-construction}
When $\operatorname{check}(p)$ is true, process the RHS from inputs to root.
Write $\operatorname{Ord}_v$ for the order produced by the constructed
assignment. Maintain
\begin{equation}
 \operatorname{set}(\operatorname{Ord}_v)=P_v,
 \qquad Req_v\preceq\operatorname{Ord}_v.
 \label{eq:order-invariant}
\end{equation}
Thus the output contains exactly the selected live axes and respects every
required relative order.

\paragraph{Input.}
Use $\operatorname{Ord}_v=I_v$.

\paragraph{Permutation.}
Place $Req_v$ first, then append the remaining child axes in their current
order. The permutation attribute lists their positions in the child.

\paragraph{Unary summation.}
Set $\operatorname{Ord}_v=\operatorname{Ord}_u|_{P_v}$. The summation
attribute lists the positions of $P_u\setminus P_v$ in the child.

\paragraph{Contraction.}
Form batch sequence $b$ by putting $Req_v|_{B_v}$ first, followed by the
remaining batch axes in a fixed order. List $K_v$ in a fixed order $k$.
For sequences $S,A$, let $\operatorname{pos}(S,A)$ list the zero-based
positions of $A$'s axes in $S$, in $A$'s order. For example,
$\operatorname{pos}((i,k,j),(j,i))=[2,0]$. Construct
\begin{equation}
\begin{aligned}
 b_\ell&=\operatorname{pos}(\operatorname{Ord}_\ell,b),&
 b_r&=\operatorname{pos}(\operatorname{Ord}_r,b),\\
 k_\ell&=\operatorname{pos}(\operatorname{Ord}_\ell,k),&
 k_r&=\operatorname{pos}(\operatorname{Ord}_r,k).
\end{aligned}
\label{eq:formal-attributes}
\end{equation}
Both operands use the same class order for each paired list. The resulting
output order is
\begin{equation}
 \operatorname{Ord}_v=b\Vert
 (\operatorname{Ord}_\ell|_{LF_v})\Vert
 (\operatorname{Ord}_r|_{RF_v}).
 \label{eq:constructed-order}
\end{equation}
Combining the assignments at all nodes yields
$\beta=\operatorname{build}(p)$.

The rewrite tree is fixed, but list lengths are not. Its passes can therefore
be emitted as \code{check} and \code{build} programs operating on finite
metadata lists at any rank in the fragment. This establishes a mathematical
program construction. The symbolic groups and expression generation used by
TEPL are described separately in Section~\ref{sec:method}.
