\subsection{Guard Certificates and Portable Core Acceptance}
\label{app:accepted-core-proof}
Guard certification establishes that every legal match satisfying the
written guard passes the generated feasibility check $E_q$.
It applies after admission checks the templates, read-once components,
equal input supports, and independent unrestricted automatic RHS fields;
supplied derivation helpers are rejected by this path.
The six sufficient cases in Table~\ref{tab:guard-certificates} establish
this implication. Otherwise, certification remains unresolved.

\begin{lemma}[Extent-independent canonical feasibility]
\label{lem:topology-abstraction}
For legal source instances with equal capture ranks and equal source axis
lists, the canonical predicate $E_q$ has the same truth value, regardless
of their extents.
\end{lemma}
\begin{proof}
Number input dimensions by capture and position. Source replay joins precisely
the dimension pairs named by the axis lists and computes output order using
those lists. Neither decision compares unpaired extents. All extent checks
succeed by source legality. Thus the input and output class sequences are
identical up to class renaming. Every predicate expression uses only
membership, order, and equality of those classes. Induction on its DAG
therefore gives the same truth value. This includes zero and singleton
extents; equality of unrelated extents never merges classes of input dimensions.
\end{proof}

\paperparagraph{Shared certification argument.}
The five structural cases construct a feasible RHS assignment for every
source axis topology admitted by their conditions. With extents set to
two, completeness gives $E_q$; Lemma~\ref{lem:topology-abstraction} extends
that result to all legal nonnegative extents. Constructor soundness then
guarantees the actual generated attributes, which need not equal the
witness assignment. The fixed-layout case instead evaluates $E_q$ directly
on its known topology and applies the same lemma.

The checker extracts facts only from positive guard conjuncts and capture
constraints, expanding preceding local lets; disjunctions contribute no
facts. Rank references must describe whole shapes, not proper subsequences.
Conflicting facts prevent certification; rank, input-dimension, and work
limits return unresolved. All written conditions, including extent and
backend restrictions, remain runtime applicability conditions.

\paperparagraph{Implementation correspondence and trust boundary.}
Permutations preserve dtype; sums preserve numeric dtype; contraction and
addition require equal numeric inputs and preserve their common dtype.
Distinct operand references and canonical contracts are required.
In a connected source tree, these equalities and unary transport give a
common capture dtype; a numeric source operation establishes its numeric
requirement. A numeric RHS without such a source operation remains unresolved.

\paperparagraph{Portable loading and execution.}
The loader regenerates the stored DAG, checks exact equality, binds its
source/target schedule to actual operation contracts and fields, and repeats
guard and dtype certification from serialized constraints. Derived descriptors
require one assignment; strict arithmetic and mixed applicability-inference
programs are rejected. The original guard and captures remain unchanged.
Runtime execution checks those conditions, evaluates the cached DAG, and
checks replacement conditions and graph legality, using checked integers
and lazy conditionals and Boolean operators without synthesis search.
A false $E_q$ is an invariant failure, not an added applicability guard.
Invalid metadata, out-of-domain inputs, and resource exhaustion are separate
outcomes. Operation semantics and implementation correspondence remain
trusted as stated in Section~\ref{sec:implementation-scope}.
Module paths, format identifiers, and work limits are archived in
\nolinkurl{evaluation/supplementary-materials/}.

\paperparagraph{Implementation of extension schemas.}
\label{app:extension-schema-implementation}
For Appendix~\ref{app:axis-extensions}'s schemas, conditions and supplied-field
equalities use literal facts, safe list identities, and finite congruence
closure over positive guard conjuncts and capture constraints.
Inverse/scatter comprehensions require exact bounds, indexed values, and
zero branches: for a legal permutation $h$,
$\sum_{j<n}[h_j=i]v_j=v_{h^{-1}(i)}$, with exactly one contributing term.
Source legality supplies permutation and length premises; sums must be
defined and representable. Before erasing helpers, every initializer must
be proved defined from safe constructors, evaluated guards, or literal
bounds. The same loading and runtime checks apply. These extensions do not
enlarge Theorem~\ref{thm:complete-synthesis}'s completeness fragment.

\paperparagraph{Acceptance guarantee.}
Section~\ref{sec:compilation-scope}'s guarantee assumes declared algebraic
semantics, the trusted contracts of Section~\ref{sec:implementation-scope},
sufficient resources, and representable metadata. Guard certification
establishes $E_q$ for every legal match satisfying the original guard.
The builder's legality argument uses membership, order, and paired extent
equality; its value argument uses finite sums and products. Both remain
valid for zero and singleton extents. The minimum-extent assumption is
needed only for completeness, not this soundness direction.
The dtype checks establish target legality; for extension schemas,
Lemma~\ref{lem:certified-extensions} supplies the constructor argument and
certification checks any supplied-field equalities. Loading preserves the
checked program and guard, and runtime evaluation executes its metadata
primitives. These facts establish the stated acceptance guarantee.
